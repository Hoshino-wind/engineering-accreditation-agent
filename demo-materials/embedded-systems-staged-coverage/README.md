# 嵌入式系统原理：分阶段覆盖演示材料

这套材料用于演示“材料上传 -> 识别审核 -> 能力图谱 -> 图谱诊断 -> 补充材料 -> 再诊断 -> 达成度/认证支撑”的完整闭环。

当前图谱诊断规则不是“有一条强支撑就算完整”，而是每个能力指标需要同时满足：

- 已审核通过的支撑关系累计强度达到 4 分以上；
- 至少来自 2 份不同材料证据；
- 待审核关系不会计入覆盖，只会显示为待处理。

因此本材料包刻意设计成先不足、后补齐：第一批材料只覆盖基础实验，并且每个指标只有 1 份证据；第二批材料补齐缺失指标，同时给已有指标补第二份独立证据。

## 演示前准备

建议使用新账号，或在系统里清空/新建一个干净课程，例如“嵌入式系统原理”。如果当前课程之前已经采纳过很多关系，旧关系会继续影响图谱诊断结果。

上传分类建议：

- `02_basic_lab_tasks_partial.csv`：实验项目清单
- `03_research_design_supplement.txt`：实验指导书
- `04_data_analysis_impact_supplement.csv`：评分表或实验项目清单
- `05_attainment_rubric_and_scores.csv`：评价结果

## 第一步：上传第一批材料，制造可诊断缺口

上传 `01-first-upload-incomplete` 文件夹里的文件：

- `02_basic_lab_tasks_partial.csv`

审核时建议把系统生成的待审关系全部采纳。

预期效果：

- 系统能识别课程“嵌入式系统原理”和 4 个基础实验项目。
- C-01-01、C-02-01、C-03-01、C-05-01 会出现支撑，但只有 1 份独立材料证据，状态应为 partial。
- C-03-02、C-04-01、C-04-02 仍没有支撑，状态应为 gap。
- 图谱诊断应能讲出两类问题：GR-04 研究链条缺失，以及已有基础指标证据来源不足。

适合讲解的话术：

“第一批实验清单能说明课程做了基础实验，但认证诊断不是只看有没有实验名，还要看研究设计、数据分析、影响考量和多来源证据。现在系统能把这些缺口明确指出来。”

## 第二步：上传第二批补充材料，补齐图谱覆盖

依次上传 `02-second-upload-supplement` 文件夹里的两个文件：

- `03_research_design_supplement.txt`
- `04_data_analysis_impact_supplement.csv`

审核时同样建议采纳待审关系。

预期效果：

- `03_research_design_supplement.txt` 补充 C-03-01、C-03-02、C-04-01、C-04-02。
- `04_data_analysis_impact_supplement.csv` 为 C-01-01、C-02-01、C-03-01、C-03-02、C-04-01、C-04-02、C-05-01 提供第二来源证据。
- 第二批全部审核通过后，7 个能力指标都应达到 covered。
- 图谱诊断应从“缺口/部分覆盖”变为“当前课程覆盖良好”，改进建议数量应明显减少或为空。

适合讲解的话术：

“补充材料不是简单堆文件，而是对诊断指出的缺口逐项回应：研究方案、数据解释、影响分析和第二证据来源都补上了。系统再次诊断后，能看到覆盖状态发生变化。”

## 第三步：上传达成度与认证支撑证据

如果要继续演示 M6 达成度评价或 M8 认证支撑，上传 `03-optional-evidence` 文件夹里的文件：

- `05_attainment_rubric_and_scores.csv`

这份文件用于说明评价项、权重、学生通过人数、达成度和后续改进触发项。它主要服务于达成度评价、报告叙述和认证支撑，不作为第二步图谱覆盖补齐的必要材料。

## 完整演示检查点

- 第一批后：有待审核关系，审核后仍有 gap 和 partial。
- 第二批第一个文件后：GR-04 从 gap 转为 partial，但部分指标仍证据不足。
- 第二批第二个文件后：7 个能力指标都具备两份独立材料证据，图谱诊断显示覆盖良好。
- 第三批后：可以继续展示达成度、改进触发项和认证支撑包。
