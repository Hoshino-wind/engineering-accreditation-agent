# MVP 范围与实施路线

## 1. 试点目标

首期选择一个专业、3～5 门课程、10～20 个实验项目、一个主评价周期和一组可比较的历史或复评样例，验证以下完整链路：

> 教学资源 → 智能识别与人工审核 → 正式能力图谱 → 覆盖与一致性诊断 → 确定性评价 → 教学改进 → 教学对象新版本 → 图谱更新 → 后续复评 → 工程认证支撑

MVP 不以覆盖全校或一次性建完全部图谱为目标，而是验证：

- 实验教学能力图谱的数据模型是否成立；
- 教师是否能以可接受成本完成候选审核；
- 图谱分析和达成度评价是否可信、可解释、可复算；
- 改进是否真正落实到教学对象变更并形成复评闭环；
- 学生材料和正式结论是否满足权限、审计与数据安全要求。

完整模块定义见[功能模块产品总图](../product/modules/README.md)，交接门槛见[端到端业务闭环](../product/end-to-end-closed-loop.md)。

## 2. MVP 功能范围

### 2.1 必须具备

| 模块 | MVP 能力 |
| --- | --- |
| M1 总览与任务工作台 | 专业/周期上下文、图谱建设进度、失败任务、我的待办和阻断项跳转 |
| M2 实验教学能力图谱 | 固定 Schema、正式节点/关系、版本、来源、路径、覆盖矩阵和基础影响清单 |
| M3 教学资源与材料 | PDF、DOCX、扫描件上传，版本、分类、解析、脱敏、来源定位和受控下载 |
| M4 智能识别与映射审核 | 实验、知识、技能、能力、Rubric、评分项及关系候选；原文对照和人工确认 |
| M5 图谱分析与一致性诊断 | 核心路径覆盖、无来源/断点/重复检查，以及大纲、指导书、评分表的关键一致性检查 |
| M6 达成度评价与统计 | 评分导入、策略版本、确定性计算、审批、周期比较和证据下钻 |
| M7 教学优化与持续改进 | 问题、原因、措施、责任人、期限、实际变更、图谱更新和复评结论 |
| M8 工程认证支撑 | 固定模板、引用校验、审批、导出和归档包 |
| M9 系统治理 | OIDC、固定角色、专业/课程数据范围、模型数据政策和关键操作审计 |

AI 不是单独的 MVP 模块。它随 M3～M5 逐步接入，用于结构抽取、候选关系和语义一致性解释；关闭模型后，人工录入、规则检查、确定性评价和完整闭环仍必须可用。

### 2.2 可以后置

- 全校多租户运营和复杂组织同步。
- 通用自然语言报表设计器。
- 自由拖拽的复杂图谱编辑器和专用图数据库。
- 自动同步所有教务系统、学习平台和实验平台。
- 移动端和学生端。
- 大规模模型微调。
- Kubernetes 与微服务拆分。

## 3. 实施原则

- 每个阶段交付可从 PC 端入口验收的垂直切片，不以空目录或孤立页面作为完成标志。
- 先固定图谱 Schema、正式事实和状态门槛，再建设智能识别和可视化。
- 候选、诊断、正式图谱和正式评价分别存储，不混用状态。
- 确定性任务使用规则和程序；AI 只处理语义候选、解释和草稿。
- 每个正式对象都要具备来源、版本、审核和数据范围。
- 产品以 1920×1080 视口和 Ant Design PC 管理端交互验收，不建设移动端适配。

## 4. 实施阶段

### 阶段 0：领域、图谱与验收基线（约 2 周）

- 确认试点专业、课程、实验项目、用户和评价周期。
- 固化毕业要求、指标点、课程目标、实验、知识、技能、能力、资源、Rubric 和评分项的术语。
- 定义首版 `GraphSchemaVersion`、允许的节点类型、关系类型和约束。
- 固化一套可人工复算的评价公式、阈值、缺失策略和评分样例。
- 建立脱敏材料、人工标注候选、图谱金标准和一致性问题样例。
- 确认 OIDC、对象存储、模型和校内部署边界。

退出条件：图谱 Schema、关系约束、数据字典、评价样例、脱敏样本、验收清单和安全责任人均获确认。

### 阶段 1：治理与工作入口（约 3 周）

- 建立 React、FastAPI、PostgreSQL、Redis、Worker 和对象存储基础工程。
- 完成 M9 的后端会话、固定角色、专业/课程数据范围和审计底座。
- 完成 M1 的工作空间上下文、任务状态、失败重试和业务待办索引。
- 建立一个专业、一个周期和一门课程的试点上下文。

退出条件：授权用户能进入正确范围，未授权请求被服务端阻断，异步任务和关键动作可追溯。

### 阶段 2：教学资源与初始图谱基线（约 3 周）

- 完成 M3 的材料上传、版本、分类、解析、来源定位、脱敏和受控下载。
- 打通 PDF、DOCX、扫描件处理、失败重试和人工分类。
- 完成 M2 的首版 Schema、基础节点目录和人工维护路径。
- 导入毕业要求、指标点、课程、课程目标和实验项目等已确认基础数据。

退出条件：教师能定位材料处理问题和原文位置；一门课程具备可供识别使用的材料与图谱上下文。

### 阶段 3：智能识别、人工审核与正式图谱（约 4 周）

- 完成 M4 的节点候选、关系候选、来源引用和原文对照。
- 支持接受、修改、合并、拆分、驳回和分级审批。
- 先以规则和人工候选打通流程，再接入可替换模型适配层。
- 完成 M2 的正式发布、版本差异、路径查询和来源链。
- 用标注集测量抽取、关系建议、引用有效性和教师修改量。

退出条件：教师能从材料完成一条“指标点—课程目标—实验—能力/技能—评分项—证据”的正式图谱路径，所有节点和关系均有来源、版本和审核记录。

### 阶段 4：图谱分析与一致性诊断（约 3 周）

- 完成 M5 的路径完整性、覆盖缺口、无来源、断点、重复和过度集中检查。
- 检查大纲、指导书和评分表中的实验名称、目标、分值和能力要求一致性。
- 区分确定性规则发现与 AI 语义判断，保存规则、模型和输入版本。
- 支持确认、驳回、豁免，以及回到 M3/M4 修正或转入 M7。

退出条件：系统能发现并处理至少一个真实覆盖问题和一个材料一致性问题，诊断可回到图谱及原文依据。

### 阶段 5：确定性达成度评价（约 3 周）

- 完成 M6 的评分导入、字段映射、范围/缺失/异常校验。
- 实现版本化评价策略和确定性计算引擎。
- 保存图谱版本、输入哈希、中间值、样本量、缺失率和程序版本。
- 建设从专业到课程、实验、评分项和证据的下钻视图。
- 用人工样例进行双算核对。

退出条件：相同输入、图谱、策略和程序版本能稳定重算，系统结果与已确认人工样例一致。

### 阶段 6：教学改进、复评与认证支撑（约 4 周）

- 完成 M7 的问题、原因、措施、负责人、期限、目标和验证计划。
- 将措施关联到课程目标、实验、材料、图谱关系或评分规则的新版本。
- 重新发布图谱、执行诊断，并用第二周期或历史样例完成复评。
- 完成 M8 的固定模板、引用校验、审批、导出和归档。
- 完成端到端权限测试、恢复演练和试点验收。

退出条件：至少一个问题完成“发现—措施—实际变更—图谱更新—复评—关闭/继续”，并生成可追溯认证支撑包。

## 5. 验收指标

### 5.1 图谱与诊断

- 正式图谱节点和关系具备有效来源、版本和审核记录：100%。
- 首个验收路径的必需关系完整率：100%。
- 诊断发现可追溯到规则、图谱版本和材料证据：100%。
- 关系建议准确率、教师修改率和单条审核时长在标注集上持续记录；目标值在基线测量后确认。

### 5.2 评价与改进

- 已确认样例的评价计算一致率：100%。
- 正式评价可追溯到图谱、策略、输入和证据：100%。
- 相同输入、策略和程序版本的重算一致率：100%。
- 已关闭问题具备实际变更、图谱更新和复评结论：100%。

### 5.3 AI 质量与人工效率

- 统计字段抽取准确率、关系建议准确率、引用有效率和语义诊断确认率。
- 无有效引用、越权上下文或结构校验失败的 AI 输出进入人工待办，不进入正式事实。
- 对比人工基线，记录单门课程材料整理、关系梳理和证据定位用时。
- 记录教师接受、修改、合并、拆分和驳回候选的比例。

### 5.4 安全与运维

- 关键越权场景阻断率：100%。
- 关键操作审计覆盖率：100%。
- 数据库与对象存储恢复演练成功。
- 生产配置和仓库无明文密钥。

## 6. 团队角色建议

- 产品/领域负责人：确认实验教学、工程认证逻辑、图谱 Schema 和验收。
- 前端工程师：图谱、审核、诊断、评价和改进 PC 工作台。
- 后端工程师：领域模块、契约、评价引擎、权限和审计。
- 数据/AI 工程师：解析、图谱候选、检索、模型适配和评测。
- 测试工程师：契约、图谱规则、计算、权限、文件和端到端测试。
- 校方安全与运维：OIDC、网络、存储、备份和上线审批。

小团队可一人承担多个角色，但正式图谱规则、评价公式和安全审批不应只由开发人员单方面决定。

## 7. 主要风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 图谱范围过大 | 首期长期无法闭环 | 先固定最小 Schema 和一门课程完整路径，再横向扩展 |
| 历史文档格式差异大 | 抽取准确率不稳定 | 建立代表性标注集，提供原文对照、人工复核和失败队列 |
| 能力术语未统一 | 节点重复、关系歧义 | 建立受控词表、别名、合并审核和版本规则 |
| 评价口径未统一 | 结果无法验收 | 阶段 0 固化样例、公式、阈值和缺失策略 |
| AI 被当作权威 | 产生错误正式事实 | 候选与正式数据分层，关键结果强制审核 |
| 教师复核成本过高 | 使用意愿下降 | 优先展示低置信度和冲突项，支持批量确认与差异预览 |
| 学生数据外泄 | 严重合规风险 | 数据分级、脱敏、模型路由、权限过滤和审计 |
| 文件、图谱和报告版本失配 | 引用和结论失效 | 固定对象版本、内容哈希、影响分析和一致性巡检 |
| 过早平台化 | 延误试点 | 限定一个专业和完整闭环，推迟图数据库、微服务和全校运营 |

## 8. 启动清单

开发首个业务切片前需要确认：

- 试点专业、课程、实验项目和评价周期。
- 一条人工确认的完整能力图谱路径。
- 图谱节点类型、关系类型、受控词表和审核责任。
- OIDC 对接联系人及测试环境。
- 对象存储、数据库和模型的部署边界。
- 学生数据分级、保留期和外部模型政策。
- 一套可人工复算的评价样例。
- 一组包含材料冲突和覆盖缺口的脱敏样例。
- 可用于开发测试的脱敏材料和标注责任人。
