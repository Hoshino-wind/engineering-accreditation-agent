# 项目分析与产品边界

## 1. 项目定位

工程认证智能体不是一个“让大模型替老师写认证材料”的工具，而是一套面向实验教学的证据治理与持续改进平台。

系统把分散在培养方案、课程大纲、实验指导书、评分表、学生报告和改进记录中的信息，组织成一条可验证的证据链：

> 认证标准 → 毕业要求 → 指标点 → 课程目标 → 实验项目 → 评分规则 → 学生证据 → 达成度 → 问题 → 改进措施 → 复评

平台的核心价值有三点：

1. **关系清楚**：说明某个实验为什么存在、培养什么能力、由什么证据证明。
2. **计算可信**：达成度计算可复现、可解释、可回溯到公式和原始证据。
3. **改进闭环**：从发现问题到采取措施，再到下一轮复评，形成连续记录。

## 2. 目标用户

### 2.1 实验教师

- 导入课程大纲、指导书、评分表和学生报告。
- 审核系统提取的实验项目、知识点、能力点和评分规则。
- 查看课程目标、实验项目和评价证据之间的缺口。
- 发起或确认课程层面的改进措施。

### 2.2 专业负责人和认证工作组

- 管理标准、毕业要求、指标点和培养方案版本。
- 审核跨课程支撑关系和证据完整性。
- 查看专业层面的达成度、异常和持续改进闭环。
- 导出带来源引用的认证支撑材料。

### 2.3 教学管理人员

- 管理专业、学期、课程、教师、角色和数据范围。
- 监控材料完整性、任务状态和审核进度。
- 查看操作日志、下载日志和模型调用记录。

### 2.4 学生

首期不建设学生操作端。学生是证据数据主体，不是主要使用者；如后续开放，应独立进行隐私评估和产品设计。

## 3. 当前主要问题

### 3.1 能力要素表达不统一

同一能力可能在课程大纲、实验目标、评分表中使用不同表述，人工梳理耗时且容易产生歧义。

### 3.2 支撑关系散落在文档中

毕业要求、课程目标、实验项目和评分项之间缺少统一的数据模型，关系常以表格、段落或经验存在。

### 3.3 材料与评价脱节

实验报告数量多，但“哪份材料支撑哪项能力、哪一条评分规则”通常不明确，抽查和复核成本高。

### 3.4 达成度缺乏版本和依据

公式、阈值、样本、缺失处理和课程版本若未固化，评价结果难以重现，也难以比较不同周期。

### 3.5 持续改进停留在文字总结

问题、措施、责任人、完成时间、复评结论缺少结构化关联，难以证明改进真正闭环。

## 4. 产品能力

### 4.1 标准与培养目标管理

- 管理认证标准、毕业要求和指标点版本。
- 管理培养方案、课程、课程目标及其版本。
- 建立标准、毕业要求、课程目标之间的正式支撑关系。

### 4.2 材料工作台

- 上传和分类课程大纲、实验指导书、评分表、实验报告等文件。
- 异步完成文本抽取、OCR、表格识别、分段和索引。
- 对抽取失败、低置信度和敏感内容给出待办。
- 保留文件版本、内容哈希、来源页码和处理链路。

### 4.3 实验教学能力图谱

- 识别实验项目、实验环节、知识点、技能点和能力点。
- 生成候选关系与解释，交由教师审核。
- 对正式关系保存创建者、依据、版本和生效状态。
- 发现课程目标未覆盖、实验重复、证据不足等结构性问题。

### 4.4 评价与证据

- 配置评分规则、评价公式、阈值、权重和缺失数据策略。
- 将评分记录、学生证据和课程目标建立可审计映射。
- 通过确定性引擎计算个体、课程目标和毕业要求达成度。
- 保存评价快照，支持重算、复核和周期比较。

### 4.5 AI 辅助分析

- 辅助理解文档、提取结构、推荐关系和解释异常。
- 对回答展示文件、页码、段落及版本引用。
- 对低置信度结果、正式关系和正式结论设置人工确认。
- 通过统一适配层接入校内模型、私有模型或合规的外部模型。

### 4.6 持续改进

- 从评价异常或证据缺口创建问题。
- 记录原因、措施、责任人、计划时间和验证方法。
- 将措施关联到课程、实验项目、资源或评分规则变更。
- 在下一评价周期自动提示复评并记录结论。

## 5. 关键业务原则

### 5.1 AI 建议不等于正式事实

AI 可以提出“该实验可能支撑某指标点”的候选关系，但只有经授权人员确认后，才能成为正式关系。

### 5.2 评价计算不交给大模型

大模型可解释结果、总结原因，但不能直接生成正式达成度。正式数值由版本化公式和确定性程序计算。

### 5.3 所有结论都应可回溯

正式关系、评价结果和改进结论应追溯到数据版本、文件片段、计算策略、操作者和时间。

### 5.4 图谱是业务关系，不只是向量相似

权威关系使用 PostgreSQL 关系表保存。pgvector 只负责召回相似内容和辅助发现候选关系。

## 6. 首期不做

- 不自动替代教师审批正式支撑关系。
- 不让大模型直接修改成绩或正式评价结果。
- 不建设通用教务系统、排课系统或在线实验平台。
- 不在首期引入微服务和 Kubernetes。
- 不承诺一次导入即可完全正确识别所有历史材料。
- 不把真实学生材料提交到公共代码仓库。

## 7. 成功标准

- 一项正式评价能够追溯到公式版本、输入数据和证据文件。
- 一条正式支撑关系能够说明建立依据、审核人和适用版本。
- 认证工作组可以从专业层面下钻到课程、实验和证据。
- AI 生成的正式用途内容具备来源引用，关键结论经过人工确认。
- 改进事项能够关联到问题、措施和下一轮复评结果。
