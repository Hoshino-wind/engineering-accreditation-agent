# M8 工程认证支撑

## 1. 模块定位

本模块从正式能力图谱、诊断结果、已批准评价和改进闭环生成固定格式的认证支撑材料，执行引用完整性、权限和敏感内容校验。

它是闭环的交付出口，不是绕过上游审核的文档编辑器。

## 2. 用户结果

- 认证工作组能够按工作空间和周期汇总完整证据链。
- 正式结论自动引用正确版本和来源。
- 缺失引用、未批准评价和未闭环问题在导出前被阻断。
- 导出包的内容范围、审批人、哈希和下载记录可追溯。

## 3. 参与角色

- 认证工作组：选择范围、生成和校验支撑包。
- 专业负责人：审核并批准正式导出。
- 课程负责人：补充课程说明和确认课程范围。
- 审计人员：查看生成、审批、下载和外发记录。

## 4. 核心对象

| 对象 | 说明 |
| --- | --- |
| `ReportTemplateVersion` | 章节结构、字段和渲染规则 |
| `SupportPackage` | 某工作空间和周期的支撑包 |
| `ReportSectionSnapshot` | 章节使用的正式事实与版本快照 |
| `PackageValidationReport` | 引用、状态、权限和敏感内容检查 |
| `PackageApproval` | 复核和批准记录 |
| `ExportArtifact` | 生成文件、内容哈希和保留策略 |

## 5. 主流程

1. 用户选择工作空间、周期、课程和报告模板。
2. 系统固定图谱、材料、诊断、评价和改进版本。
3. 系统生成章节草稿和证据索引。
4. 用户补充允许人工撰写的说明内容。
5. 系统校验正式状态、引用有效性、缺失项、数据范围和敏感内容。
6. 阻断项返回事实所属模块修正。
7. 认证工作组复核差异和来源。
8. 专业负责人批准支撑包。
9. 系统生成带哈希的导出文件并记录下载。
10. 支撑包随工作空间归档。

## 6. 状态与规则

```text
draft → generating → validating → changes_required / ready_for_review
  → approved → exported → archived
```

- 报告只读取已发布、已确认或已批准的业务版本。
- 正式事实不能在报告中直接修改；必须返回所属模块修正。
- 每个正式结论必须能定位到来源或计算快照。
- AI 生成说明必须有引用并经过人工复核。
- 导出前重新执行权限、敏感内容和引用校验。
- 批准后的内容变化必须创建新支撑包版本。
- 下载、批量导出和外发必须记录用途和操作者。

## 7. 输入与输出

上游输入：

- [实验教学能力图谱](02-ability-graph.md)的正式节点、关系和来源链；
- [教学资源与材料](03-teaching-resources.md)的证据版本；
- [图谱分析与一致性诊断](05-graph-analysis-diagnosis.md)的确认结果；
- [达成度评价与统计](06-attainment-evaluation.md)的已批准运行；
- [教学优化与持续改进](07-teaching-improvement.md)的闭环记录。

输出：

- 已批准 `support_package_id`；
- PDF、DOCX 或受控压缩包等导出产物；
- 证据索引和版本清单；
- 校验报告、审批记录和下载审计。

## 8. 页面范围

- 固定模板支撑包列表和创建向导。
- 章节预览、来源侧栏和缺失项列表。
- 校验报告和阻断项跳转。
- 版本差异与审批。
- 受控导出、下载记录和归档详情。

## 9. 非目标

- 不建设通用自然语言报表设计器。
- 首期不建设拖拽模板和任意指标设计器。
- 不允许在报告中覆盖上游正式事实。
- 不把无引用 AI 文本直接放入正式材料。
- 不提供不受权限和审计控制的批量下载。

## 10. 验收标准

- 能为一个试点课程生成包含能力图谱、材料一致性、评价和改进记录的支撑包。
- 正式结论具备有效来源或计算快照的比例为 100%。
- 未批准评价、失效引用和未授权内容能够阻断导出。
- 批准后修改会生成新版本。
- 导出文件具备内容哈希、版本、审批和下载记录。
- 归档后仍可按当时版本复核证据链。

## 11. 当前 PC 原型切片

当前 `/support` 已实现 1920×1080 Ant Design PC 工作台，用一屏串联“支撑包—版本快照—章节预览—完整校验—复核/导出准备”：

- 顶部展示支撑包、需修正、待复核和已批准数量，均明确标记为试点示例数据。
- 左侧支撑包队列支持按固定模板、状态和关键词筛选。
- 中部展示支撑包范围、模板版本、M2～M7 来源快照、流程状态、章节引用数量和正式结论预览。
- 章节切换会同步更新正文摘要与引用，证据索引抽屉可查看来源对象、冻结版本、状态、内容哈希和结论引用。
- 右侧固定展示 8 项导出门槛，并为上游事实阻断提供“返回 M6 / 返回 M7”的真实导航。
- PDF、DOCX 和证据压缩包配置仅保存本地草稿；正式复核与导出按钮保持禁用。

试点主案例为 `SP-2026-001 实验教学认证支撑包 v1.2`，课程为计算机网络，模板为“实验教学能力达成与持续改进 v1.3”。当前已固定图谱、材料和诊断版本，但 `eval-2026-071` 尚未批准、`qi-2026-017` 尚未关闭，因此处于 `changes_required`，不能提交复核或导出。

### 11.1 已固化的校验规则

前端纯规则 `validateSupportPackage` 当前执行 8 项检查：

1. 模板、范围和来源版本已经固定；
2. 图谱版本为正式发布状态；
3. 每条正式结论至少具备一个来源引用；
4. 当前操作者具备完整专业和课程数据范围；
5. 敏感内容扫描通过；
6. 内容哈希已经生成；
7. 所引用的评价运行已经批准；
8. 所引用的改进问题已经闭环。

任一检查失败都会阻断复核和导出。只有全部校验通过、支撑包已经批准且审批快照哈希与当前内容哈希一致时，才具备受控导出条件；批准后内容发生变化必须创建新版本。以上规则已有自动化测试。

## 12. 当前边界与后续接口

- 当前页面使用 `prototypeOnlySupportPackages`，不伪装成服务端持久化数据。
- 章节正文只显示冻结事实的摘要和引用，不允许在报告内编辑或覆盖上游正式事实。
- 正式支撑包创建、异步生成、权限/敏感内容复检、审批、产物生成、下载审计和归档仍归后端 `reporting` 模块。
- 后续 API 应首先提供支撑包列表/详情、版本快照、章节快照、校验报告、审批和受控导出；服务端必须重复执行全部校验，不能信任前端按钮状态。
- PDF、DOCX 和证据压缩包都必须记录模板版本、内容哈希、审批快照、导出用途、操作者和下载记录。
