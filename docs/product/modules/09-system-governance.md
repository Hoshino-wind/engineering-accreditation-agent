# M9 系统治理

## 1. 模块定位

本模块统一管理身份、角色、专业/课程数据范围、模型数据政策和不可变审计事件。

治理页面保持简单，但所有业务读取、写入、审核、下载和导出都必须经过服务端权限校验。

## 2. 用户结果

- 用户只访问被授权的专业、课程、材料和图谱。
- 管理员能配置固定角色和数据范围。
- 审计人员能追溯谁在何时对什么对象执行了什么动作。
- 高风险下载、导出、权限提升和模型调用可识别。

## 3. 参与角色

- 普通教师、课程负责人、专业负责人、认证工作组；
- 系统管理员；
- 安全管理员；
- 审计人员；
- API、Worker、迁移和备份服务身份。

## 4. 核心对象

| 对象 | 说明 |
| --- | --- |
| `UserIdentity` | 学校身份标识 |
| `RoleAssignment` | 用户在特定范围的角色 |
| `DataScope` | 学院、专业、课程、教学班和周期范围 |
| `Session` | 后端会话、过期和撤销 |
| `ModelDataPolicy` | 数据级别与允许模型范围 |
| `AuditEvent` | 操作者、动作、对象、范围、结果和时间 |
| `RiskSignal` | 越权、异常下载、批量导出或权限提升 |

## 5. 主流程

1. 用户通过学校 OIDC 登录并建立后端会话。
2. 系统同步用户身份和角色分配。
3. 用户选择有权访问的工作空间。
4. API 对每次请求执行动作权限和数据范围校验。
5. 关键动作以追加事件记录。
6. 高风险事件触发告警和调查。
7. 权限撤销后会话和缓存授权及时失效。

## 6. 状态与规则

会话：

```text
anonymous → authenticating → active → expired / revoked
```

角色分配：

```text
pending → active → expired / revoked
```

- 默认拒绝，没有明确授权即不可访问。
- 前端隐藏菜单不是安全控制。
- 审计事件只追加，不提供编辑。
- 不记录密码、令牌、密钥、完整学生正文或不必要的成绩明细。
- 学生材料进入模型前必须满足数据政策和用途限制。
- API、Worker、迁移和备份使用独立服务身份。

## 7. 输入与输出

输入：

- OIDC 身份和组织同步信息；
- 管理员角色配置；
- 所有模块的关键业务事件；
- 数据分级和模型使用政策。

输出：

- 用户、角色、数据范围和可执行动作；
- 模型能力决策；
- 可检索业务时间线；
- 风险告警和受控审计导出。

## 8. 页面范围

- 登录回调和失败页。
- 用户、角色和数据范围管理。
- 当前身份与授权说明。
- 审计事件、业务对象时间线和风险事件。
- 模型数据政策和调用记录。

## 9. 非目标

- 不替代学校统一身份、HR 或组织管理系统。
- 不建设通用日志与性能监控平台。
- 不在审计页面修改业务状态。
- 不允许共享管理员账号或无范围全校访问。

## 10. 验收标准

- 关键越权场景阻断率为 100%。
- 关键业务操作审计覆盖率为 100%。
- 角色撤销后现有会话按策略失效。
- 审计记录不包含令牌、密钥和完整敏感正文。
- 不符合政策的模型调用在发送数据前被阻断。
