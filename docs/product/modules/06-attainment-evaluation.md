# M6 达成度评价与统计

## 1. 模块定位

本模块使用正式能力图谱、受控评分输入和版本化评价策略执行确定性计算，生成不可变、可复算、可下钻的评价运行快照。

大模型可以解释结果，但不得参与正式数值计算。

## 2. 用户结果

- 评价负责人能够配置并验证适用的评价策略。
- 评分数据在计算前完成范围、缺失和异常校验。
- 同一输入、策略和程序版本可以得到同一结果。
- 用户可以从专业结果下钻到课程、实验、评分项和证据。
- 未达标和数据质量问题可以直接转为改进问题。

## 3. 参与角色

- 课程负责人：准备评分数据并确认课程范围。
- 评价负责人：配置策略、执行评价和处理校验问题。
- 专业负责人：复核并批准正式评价。
- 认证工作组：查看下钻结果和周期对比。
- 审计人员：查看运行、审批和导出记录。

## 4. 核心对象

| 对象 | 说明 |
| --- | --- |
| `ScoreImportBatch` | 一次受控评分数据导入 |
| `ScoreRecord` | 原始或汇总评分记录 |
| `EvaluationPolicyVersion` | 公式、权重、阈值和缺失处理策略 |
| `EvaluationInputSnapshot` | 本次计算使用的版本和输入哈希 |
| `DataValidationReport` | 样本、缺失、异常和映射校验结果 |
| `EvaluationRun` | 一次不可变评价执行 |
| `EvaluationResult` | 各层级结果、中间值和结论 |
| `EvaluationApproval` | 复核和批准记录 |

## 5. 主流程

1. 评价负责人选择工作空间、周期和评价范围。
2. 系统固定能力图谱版本和正式关系集合。
3. 用户导入评分数据并完成字段映射。
4. 系统执行样本范围、重复、缺失、异常和关系完整性校验。
5. 用户选择或新建评价策略版本。
6. 用人工样例预演并确认中间值。
7. 系统执行确定性评价并保存完整输入快照。
8. 负责人逐层复核结果和异常。
9. 专业负责人批准后形成正式评价快照。
10. 未达标项和数据质量问题可创建持续改进问题。

## 6. 状态与规则

```text
draft
  → validating
  → blocked / ready
  → running
  → awaiting_review
  → approved
  → superseded
```

- 校验失败的运行不得进入正式计算或批准状态。
- 策略版本发布后不可原地修改。
- 评价运行保存输入哈希、图谱版本、策略版本和程序版本。
- 正式运行批准后不可修改；修正输入需创建新运行。
- 学生明细遵循更严格的数据范围和导出权限。
- 日志不记录不必要的个人成绩明细。
- AI 解释必须基于已计算结果和有效引用，不能修改数值。

## 7. 输入与输出

上游输入：

- [实验教学能力图谱](02-ability-graph.md)的正式图谱和评分关系；
- 受控评分数据；
- 已验证评价策略。

向下游输出：

- 已批准 `evaluation_run_id`；
- 各层级结果、中间值、样本量和缺失率；
- 未达标、异常和数据质量问题；
- 周期比较所需快照。

主要消费者：

- [图谱分析与一致性诊断](05-graph-analysis-diagnosis.md)；
- [教学优化与持续改进](07-teaching-improvement.md)；
- [工程认证支撑](08-accreditation-support.md)。

## 8. 页面范围

- 评分数据导入和字段映射。
- 数据质量校验报告。
- 评价策略版本管理和人工样例预演。
- 评价运行列表、详情和审批。
- 专业—课程—实验—评分项下钻。
- 周期对比和创建改进问题入口。

### 8.1 首个评价工作台

首个纵向切片优先做细“能不能算、怎么算、算出了什么、谁来确认”：

1. 左侧“评价对象”按课程、状态和课程目标检索，明确区分待复核、已批准、已阻断和未达标。
2. 中部固定展示计算公式、评分项得分率、权重、贡献值、合计值、阈值和达成结论。
3. 右侧固定展示图谱、策略、评分快照、样本范围和逐项输入就绪检查。
4. 完整计算明细保存并展示输入快照哈希、程序版本、中间值和证据引用。
5. 缺失评分、权重不闭合或正式关系不完整时，只展示阻断原因，不生成结果。
6. 复核结论先作为本地草稿验证交互，正式提交必须等待后端审批用例和权限边界接入。

本切片不把评分导入、策略编辑、运行审批、周期对比和创建改进问题揉进同一屏；这些能力分别在后续子流程中补齐。

## 9. 非目标

- 不让大模型生成正式数值。
- 不在本模块修改原始成绩。
- 不用可视化结果替代中间值和计算依据。
- 不在未确认评价公式时提供“默认正确”的正式结果。

## 10. 验收标准

- 一套人工样例与系统结果一致率为 100%。
- 相同输入、策略和程序版本重算结果一致。
- 已批准结果能够沿图谱下钻到课程、实验、评分项和证据。
- 缺失、异常和版本不一致能够阻断正式运行。
- 已批准运行具备完整输入和审批快照。
- 未达标结果可以创建带来源的改进问题。

## 11. 当前实现边界

当前 PC 原型已实现：

- 6 个显式标记的试点评价对象及组合筛选；
- 4 个就绪对象、2 个阻断对象的输入状态；
- 一套可人工复算的加权达成度计算与单元测试；
- 图谱、策略、程序、评分快照和输入哈希追溯；
- 完整计算明细抽屉，以及结果确认/申请重算的本地草稿。

当前仍为原型数据，未接入评分导入、策略持久化、正式评价运行、审批、学生明细权限、导出和 M7 问题创建。禁用的“运行评价”和“提交确认”不伪装成功。
