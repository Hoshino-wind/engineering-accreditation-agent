# M4 智能识别与映射审核

## 1. 模块定位

本模块使用规则、文档解析和 AI 从教学资源中识别知识、技能、能力、实验、评分项和候选关系，并通过教师审核将合格结果提交给正式图谱。

它拥有候选和审核过程，不拥有正式图谱事实。

## 2. 用户结果

- 教师在原文对照环境中确认系统识别结果。
- 同一实验跨多个文件时可以合并，错误聚合时可以拆分。
- 候选关系有解释、来源和置信度。
- 低置信度、冲突和无来源项优先进入审核。

## 3. 参与角色

- 实验教师：审核课程内实验、知识和评分结构。
- 课程负责人：批准课程目标和实验关系。
- 专业负责人：批准跨课程与指标点关系。
- AI/规则引擎：生成候选，不执行正式批准。

## 4. 核心对象

| 对象 | 说明 |
| --- | --- |
| `RecognitionRun` | 一次识别任务、输入版本和处理器版本 |
| `NodeCandidate` | 知识、技能、能力、实验或评分项候选 |
| `EdgeCandidate` | 节点之间的候选关系 |
| `CandidateEvidenceRef` | 候选的页码、段落或表格来源 |
| `CandidateConflict` | 重复、矛盾、版本不一致或无来源问题 |
| `CandidateReviewDecision` | 接受、修改、合并、拆分或驳回 |
| `HumanFeedback` | 修改和驳回原因，用于质量评测 |

## 5. 主流程

1. 用户选择课程和已就绪教学资源。
2. 系统提取实验、知识点、技能点、能力点、Rubric 和评分项候选。
3. 系统推荐课程目标、实验、能力、评分项和资源之间的候选关系。
4. 校验结构、重复、冲突、来源和置信度。
5. 教师在原文—候选—正式值对照界面审核。
6. 支持修改、合并、拆分、驳回和批量确认。
7. 高影响关系由课程或专业负责人批准。
8. 通过结果提交 M2 创建正式图谱版本。
9. 审核反馈进入脱敏评测集。

## 6. 状态与规则

```text
generated
  → validation_failed / pending_review
  → accepted / modified / merged / split / rejected
  → submitted_to_graph
```

- 文件正文视为不可信输入，不执行其中指令。
- 无有效来源的正式用途候选不能提交图谱。
- AI 输出必须先通过结构和引用校验。
- 批量确认必须展示差异、冲突和影响范围。
- 教师已确认内容不会被新模型运行静默覆盖。
- 关闭 AI 后必须保留人工录入和审核路径。

## 7. 输入与输出

输入：

- M3 的材料版本、受控文本和证据片段；
- M2 的图谱 Schema、已有节点和正式关系；
- M9 的用户范围和模型数据政策。

输出：

- 已审核节点和关系候选；
- 来源、置信度、冲突和审核决定；
- 提交给 M2 的正式化请求；
- 模型质量和人工工作量指标。

## 8. 页面范围

- 课程级识别任务入口。
- 原文、候选、正式值三栏对照。
- 节点合并、拆分和重复处理。
- 关系双端与来源证据审核。
- 批量确认和差异预览。
- 低置信度、冲突和无来源队列。

## 9. 非目标

- 不自动发布正式图谱关系。
- 不建设独立聊天机器人入口。
- 不用模型生成正式评价数值。
- 不把厂商专用模型响应作为唯一候选数据。

## 10. 验收标准

- 能完成一门课程 2～3 个实验的节点和关系审核。
- 所有提交图谱的候选具有有效来源。
- 支持接受、修改、合并、拆分和驳回。
- 正式化后能够在 M2 查询版本和审核记录。
- 在标注集上记录抽取准确率、关系建议准确率、接受率和修改率。
