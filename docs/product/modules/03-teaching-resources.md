# M3 教学资源与材料

## 1. 模块定位

本模块同时负责两类不同事实：可被实验复用的逻辑教学资源，以及材料从上传到可引用证据的完整治理。材料处理包括安全校验、分类、版本、解析、脱敏、来源定位和受控访问。

它拥有教学资源的稳定身份和版本，以及原始文件、材料版本和证据片段；不拥有资源与能力、实验之间的正式图谱关系，也不拥有评价结论。

## 2. 用户结果

- 教师能够把材料归属到正确课程、周期和材料类型。
- 教师能够登记设备、软件环境、数据集、案例、仿真平台和指导资源，并维护其有效版本。
- 每份材料都有版本、哈希、处理状态和来源位置。
- 解析失败、低置信度和敏感内容能够被发现和处理。
- 下游可以稳定引用某个文件版本的具体页码、段落或表格位置。

## 3. 参与角色

- 教师：上传和确认自己课程的材料。
- 材料管理员：批量导入、分类和处理异常。
- 课程负责人：确认材料归属与有效版本。
- 审计人员：查看高风险访问和下载记录。

## 4. 核心对象

| 对象 | 说明 |
| --- | --- |
| `TeachingResource` | 可被多个实验复用的逻辑教学资产 |
| `TeachingResourceVersion` | 资源能力边界、适用范围和有效状态的不可变版本 |
| `Material` | 同一逻辑材料的稳定身份 |
| `MaterialVersion` | 不可变文件版本、对象键与内容哈希 |
| `MaterialClassification` | 课程、周期、类型和置信度 |
| `EvidenceFragment` | 页码、段落、表格坐标和内容哈希 |
| `SensitiveContentFinding` | 个人信息或受限内容标记 |
| `ProcessingJobRef` | 指向任务中心的处理任务引用 |

材料类型至少包括：课程大纲、实验指导书、实验项目清单、评分表、学生报告、评价结果和改进记录。

教学资源类型至少包括：实验设备、软件环境、数据集、案例、视频、仿真平台、测试工具和指导资源。教学资源可以引用一个或多个材料版本作为说明或使用依据，但教学资源不等同于上传文件。

## 5. 主流程

1. 用户选择专业、课程、周期和材料类型。
2. API 签发短时上传地址，浏览器直传对象存储。
3. 系统校验文件扩展名、MIME、文件头、大小和哈希。
4. 恶意文件扫描通过后创建材料版本。
5. Worker 解析文本、表格或扫描页并保存来源位置。
6. 系统检测敏感内容，生成受控文本视图。
7. 用户确认或修正自动分类。
8. 课程负责人确认材料版本的业务有效性；需要形成教学资源时，复用或创建 `TeachingResourceVersion`。
9. M4 使用受控文本生成节点和关系候选，并把资源候选解析到稳定资源版本。
10. M2 固定资源版本引用并发布 `USES` / `ENABLES` 关系；下游通过证据引用使用材料，不复制正文。

## 6. 状态与规则

```text
upload_pending
  → verifying
  → processing
  → awaiting_classification
  → ready

verifying / processing → failed
verifying → quarantined
ready → superseded / archived
```

教学资源生命周期独立为：

```text
draft → active → superseded / archived
```

- 解析、脱敏和分类未完成的材料不能进入智能识别与审核。
- 相同哈希重复上传时提示复用或建立新业务版本。
- 原始文件、解析产物、脱敏片段和导出副本分区存储。
- 对象键不得包含姓名、学号等个人信息。
- 已被正式关系或评价引用的材料版本不得静默删除。
- 删除材料时必须评估并处理派生文本、向量、缓存和报告引用。

## 7. 输入与输出

上游输入：

- [总览与任务工作台](01-dashboard-and-tasks.md)的专业和周期上下文；
- [实验教学能力图谱](02-ability-graph.md)的课程和资源类型；
- [系统治理](09-system-governance.md)的访问决策。

向下游输出：

- `material_version_id`；
- `teaching_resource_id` / `teaching_resource_version_id`；
- 材料类型、课程、周期和有效状态；
- `evidence_fragment_id` 及来源坐标；
- 受控文本视图；
- 处理质量和敏感内容标记。

主要消费者：

- [智能识别与映射审核](04-intelligent-recognition-review.md)；
- [图谱分析与一致性诊断](05-graph-analysis-diagnosis.md)；
- [工程认证支撑](08-accreditation-support.md)。

## 8. 页面范围

- 材料列表与批量筛选。
- 教学资源目录、适用范围和版本历史。
- 上传向导和重复文件提示。
- 材料详情、版本历史和来源预览。
- 分类确认、处理状态和失败重试入口。
- 受控下载与归档操作。

## 9. 非目标

- 不在本模块确认正式图谱节点和关系。
- 不在本模块声明资源培养、训练或支撑哪些能力；这些关系由 M2 审核发布。
- 不提供任意文件网盘能力。
- 不默认把学生报告发送给外部模型。
- 不承诺所有历史扫描件完全自动解析。

## 10. 验收标准

- PDF、DOCX 和扫描件各一份能够完成受控上传。
- 文件版本、哈希、课程、周期和材料类型完整保存。
- 解析结果可以定位到原文件页码、段落或表格。
- 危险文件被隔离，解析失败可查看原因并重试。
- 未授权用户无法查看、下载或检索材料。
- 被下游引用的版本能够长期稳定访问和校验哈希。
- 一个教学资源版本能够被 M2 以稳定 ID 引用，而不复制资源内容。

## 11. 当前实现阶段

当前 PC 端原型已覆盖：

- 课程、材料类型、处理状态和关键词组合筛选；
- 材料版本、哈希、敏感级别、来源覆盖率和处理流水线查看；
- 解析失败、待分类和隔离材料的原因与下一步提示；
- 证据片段的坐标、原文预览和内容哈希查看；
- 真实文件上传、对象结构校验、文件头校验、压缩包路径穿越检查；
- EICAR 内置特征扫描，以及本机安装 ClamAV 后的自动调用；
- SQLite 材料元数据、本地内容寻址对象目录和失败重试；
- TXT、Markdown、CSV、DOCX、XLSX 和带文本层 PDF 的本地解析；
- 图片和扫描 PDF 通过可配置的 DeepSeek-OCR OpenAI 兼容端点解析；
- 配置 DeepSeek 通用 API 密钥后对文本结果执行 JSON 证据结构化。

当前页面和 API 实现重点仍是材料治理；独立的 `TeachingResource` / `TeachingResourceVersion` 目录与 M2 稳定引用接口尚未接入，现有前端 `TeachingResource` 命名暂时实际承载的是材料视图模型，后续迁移时不得继续把两者视为同一对象。

M3 页面以本地 API 数据为准，只有在 API 无法连接时才展示并明确标记离线示例。默认运行不需要 PostgreSQL、Redis 或 MinIO。当前尚未完成个人信息识别/脱敏、服务端数据范围授权、材料版本合并与归档、批量任务队列和正式 M4 交接。
