# 现有实验资料盘点

## 1. 盘点范围

本次对用户提供的“实验资料”压缩包进行了只读结构盘点，用于验证产品需求和数据模型。盘点结果只记录文件数量、类型和结构特征，不复制正文，不记录真实姓名、学号、成绩等个人信息。

原始文件及解压内容未提交到 Git 仓库。

## 3. 资料反映出的业务对象

现有资料至少包含以下对象：

- 课程、学期、教师和教学班。
- 课程大纲、课程目标和毕业要求支撑关系。
- 实验项目、实验目的、内容、步骤、环境和成果要求。
- 评分项、分值、等级描述和达成度数据。
- 学生提交物、实验结果、教师评价和成绩。

这些对象不能只作为全文保存，还需要转换为可版本化的结构化数据，同时保留原文定位。

## 4. 对系统设计的直接影响

### 4.1 文档类型不能只靠文件扩展名判断

相同格式可能分别是大纲、指导书、评分表或学生报告。导入流程需要“自动分类 + 人工校正”，并保存分类置信度。

### 4.2 同一实验可能跨多个文件

实验清单、指导书、评分表和报告可能分别描述同一实验。系统需要生成稳定的实验项目标识，并允许教师合并、拆分和纠错。

### 4.3 页码和表格位置是证据的一部分

认证复核需要定位原始依据。抽取后的每个片段应保留对象键、文件版本、页码或段落、表格位置和内容哈希。

### 4.4 个人信息保护必须前置

学生报告和成绩材料可能包含姓名、学号、班级、联系方式或账号信息。系统应在解析、向量化、模型调用和导出环节分别执行最小化、脱敏和权限控制。

### 4.5 历史资料质量不会完全一致

扫描件、旧版 Word、复杂表格和非统一命名都会造成解析差异。任务工作台必须展示失败原因、低置信度字段和人工复核状态。

## 5. 建议的导入流程

1. 上传文件到对象存储，生成对象键、哈希和文件版本。
2. 病毒与文件类型检查，禁止危险格式进入解析链。
3. 自动分类并由用户确认课程、学期和材料类型。
4. 异步解析文本、表格和扫描页，保存来源坐标。
5. 检测并标记个人信息，生成受控文本视图。
6. 提取实验项目、目标、评分项和候选关系。
7. 教师在审核工作台确认、修改或驳回。
8. 对允许检索的脱敏片段生成向量索引。
9. 将正式关系和版本写入主数据库，并记录审计日志。

## 6. 样本集建设建议

正式开发前，从不同课程和文件类型中选择一批经授权、脱敏的代表性样本，人工标注：

- 文档类型与课程归属。
- 实验项目边界。
- 课程目标、能力点和评分项。
- 原文位置与正确关系。
- 需要屏蔽的个人信息。

该样本集用于衡量解析准确率、关系推荐准确率和版本升级回归效果。样本原件应存放在受控对象存储或私有测试环境，不进入代码仓库。
